# Hard-coded Hebrew string inventory

`inventory.csv` lists every hard-coded Hebrew UI string in `src/` outside `src/lib/locales/*`. It is the input for moving strings into the i18n locale files. No UI code is changed by this inventory.

- Generated by `python3 i18n/extract_inventory.py > i18n/inventory.csv`. The script is read-only and deterministic, so re-run it after code changes.
- One row per occurrence. Columns:
  - `id`: `he-NNNN`, positional, so it changes on regeneration.
  - `screen/route`: `src/routes/a.b.tsx` → `/a/b`. Components are listed as `component:<path>` and libs as `lib:<path>`.
  - `file:line`
  - `kind`: `string` (quoted literal), `template` (backtick literal, one row per Hebrew line), or `jsx_text` (JSX text node).
  - `core_path`
  - `hebrew_source`: whitespace-collapsed.
- Comments are skipped.
- `core_path = yes` means a student-facing screen, component or lib. Admin/teacher screens, admin components, staff-only reports (PDF/DOCX/HTML BEQA reports), import/export and the AI-agent backend, and `/beqa-spike` (dev only) are `no`. This is broader than the plan's ~263 "core path" count, so filter further as needed.
